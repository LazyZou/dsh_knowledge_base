# PDF 知识库

把 PDF 变成可以检索、可以提问的知识库。插件在左侧边栏注册一个入口，打开后是一个全局面板：上传 PDF、阅读解析出的正文、浏览切分出的知识条目，并针对这些文档提问。扫描件（图片型 PDF）也能收录，识别出文字后同样可以检索和提问。

## 文本清洗与主题分组

入库前每一页都会清洗：去掉页码与页眉页脚、装饰线（`-----`、`=====`、`······`）、纯符号行、零宽字符与控制字符、私用区与替换字符；合并被拆行的碎片、去掉逐页重复的行。清洗后有效字符不足 32 个的片段不会写入知识库。

目录页的点线引导行（`18.9 图算法的分析 ...... 103`）连同 OCR 在点线上生成的伪文字（`sesenecesscesences…`、`eee reer rere`）一并丢弃：判据是连续点线/下划线、行尾「点线 + 页码」，以及拉丁字母串重复率过低、整行词形重复率过低。含中文的行不受字母判据影响。

每个知识分块带一个主题：按文档顺序扫描，遇到章节标题（`第 3 章 图`、`2.2.3 部署`、`Chapter 4`、`二、安装部署`）开新主题，正文归入当前主题；含 `=`、`{`、`//` 的代码行与行号不会被当成标题。同一章、同一节的多种 OCR 写法按章号/节号合并成一个主题；章标题取保留汉字最多的那种写法，避免把 `第 18 章 ARK` 这种 OCR 残片当成主题名。每页重复的页眉页脚只保留首次出现，其余丢弃。没有章节标题的文档按高频词分组。面板「知识」页按主题折叠展示，并支持关键词筛选。

升级前入库的文档在下次打开时按新规则自动重建分块与主题（保留已有的 OCR 文本），不需要重新上传。

## 能做什么

- **批量上传 PDF**：点「批量上传 PDF」可以一次选多个文件，也可以把多个文件一起拖进面板。文件先流式送到宿主进程，再由后台队列逐个解析入库：关掉面板、切到别的页面都不影响进度，回到「任务」页签就能看到每份文件的状态。单文件最大 500 MB，全部在本机解析，不上传任何外部服务。
- **查看内容**：按页展示解析出的文字，长文档可以逐页阅读。扫描页会先显示页面图像，识别后补上文字。
- **识别扫描件**：扫描页以「待识别」状态入库。批量导入默认顺带识别；也可以在「内容」页点「识别扫描页」，把它作为后台任务连续分批跑到完成，随时可以取消。只处理没有文字层的页，结果写回文档，重复页与已识别页不会再次消耗识别成本。
- **查看任务进度**：「任务」页签列出后台导入与识别任务，显示完成比例、每份文件成功/失败、失败原因（如「文件超过 500 MB」「PDF 已加密」），可以取消进行中的任务、清除已结束的记录。
- **查看知识**：展示从正文切分出的知识条目（每条约 900 字，带页码），这是检索与回答的真实依据。
- **提问**：问题只在已收录的文档里检索。找到相关段落后，用原文句子组合出回答，并标注「文档标题 · 第几页」。没有命中时明确提示「知识库缺少相应知识」，而不是凭空作答。
- **给对话里的助手使用**：注册了 `kb_search`、`kb_documents`、`kb_read_document`、`kb_add_document`、`kb_import`、`kb_ocr`、`kb_jobs`、`kb_remove_document` 八个工具（`kb_import` 批量导入并立即返回任务 id，`kb_jobs` 查进度），并在系统提示中要求助手在回答文档相关问题时先查知识库、引用出处；查不到时如实说明知识库没有该知识。文档列表里 `ocrPending` 不为 0 时，助手会先调用 `kb_ocr` 再下结论。

## 存储位置

文档与索引存在 `$DSH_HOME/pdfkb`（默认 `~/.dsh/pdfkb`）：

- `index.json`：文档清单与统计（含扫描页待识别数量）。
- `jobs.json`：后台任务队列（最近 20 个任务），记录每份文件的结果与进度；重启后仍可查看，未完成的任务会重新排队。
- `docs/<id>.json`：单份文档的逐页正文、识别出的文字与知识条目。
- `docs/<id>/p<页号>.jpg|png`：扫描页的页面图像（原始分辨率），只在需要识别或预览时读取。
- `docs/<id>/p<页号>.vision.png`：页面图像的缩小副本，只供视觉模型识别使用，可随时删除。

删除文档会同时删除它的知识条目与页面图像。卸载插件不会删除这些文件，需要时手动清理该目录即可。

## 扫描件识别（OCR）

识别按「本机优先、模型兜底」分两级，都不可用时会明确报 `OCR_UNAVAILABLE`，不会假装识别成功：

1. **本机 Tesseract**：装了就用，不消耗 token、不联网。会自动探测常见安装路径（也可在插件配置里指定 `tesseractPath`），并优先使用 `chi_sim+eng` 语言包（中文扫描件需要 `chi_sim.traineddata`）。识别用原始分辨率的页面图像，字形更清晰、错字更少。
2. **视觉模型工具**：本机没装 Tesseract 时，调用已安装的视觉插件提供的 `vision_ocr` 工具，把页面图像交给视觉模型识别。

节省成本的做法：只对文本层为空的页做识别；页面图像按原始分辨率保存（给 Tesseract 用），另存一份缩到 1600 像素宽的副本专供视觉模型（图像 token 约为原图的四分之一）；识别结果落盘缓存；同一份文档里图像完全相同的页只识别一次；多页并行识别（默认 4 路，可配置）；每次调用只处理有限页数（默认 6 页，可调），面板会显示剩余页数。

识别结果会做文本清理：去掉汉字之间以及汉字与中文标点之间的空格，并把夹在中文之间的半角 `,` `.` `;` `:` `?` `!` 转成对应全角标点，避免空格切断中文二元组分词。

识别精度取决于页面图像质量与所选后端：清晰扫描件通常可用；手写体、低分辨率、倾斜页面容易出错，必要时请换更清晰的原件。

## 解析能力与限制

内置纯 JavaScript 的 PDF 解析器，支持：交叉引用流与对象流（ObjStm）、FlateDecode/ASCIIHex/ASCII85、页树继承资源、Form XObject 递归、`Tj`/`TJ`/`'`/`"` 文本操作符、ToUnicode CMap（含 `bfchar`/`bfrange`）、Identity-H 双字节编码、WinAnsiEncoding，以及 Standard 安全处理器 R2–R4（RC4 与 AES-128）的空口令文档。

页面图像按原始分辨率保存，支持 JPEG（DCTDecode）直接取出，8 位灰度/彩色 FlateDecode 与 CCITT G3/G4 传真编码（扫描件最常见的编码）重新编码为 PNG；JPEG2000、JBIG2 暂不支持。

尚未支持：

- 需要打开口令的加密文档（会明确报错，不会输出乱码）。
- AES-256（PDF 2.0，V5/R5）加密文档。
- 无文字层且页面图像编码不受支持的扫描件（会提示无法识别）。
- 复杂排版（多栏、表格）的阅读顺序可能不完全准确；这是文本抽取的固有限制。

## 检索与回答方式

检索使用 BM25（中文按单字 + 二元组切词），回答是抽取式的：从命中的段落里挑与问题重合度最高的原句拼接，因此回答不会出现文档里没有的内容。面板不调用大模型；需要大模型的总结式回答时，请在对话里让助手用 `kb_search` 工具查询。

## 配置项

在 profile 的插件行 `config` 里可选项：

- `ocrEngine`：`auto`（默认，先本机后模型）、`tesseract`、`vision`。
- `tesseractPath`：指定 tesseract 可执行文件路径。
- `pagesPerRun`：每次识别的页数，默认 6，范围 1–40。
- `concurrency`：并行识别的页数，默认 4，范围 1–8。本机 Tesseract 是 CPU 密集型，多核机器调大更快。
